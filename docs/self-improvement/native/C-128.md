# C-128 — `process::exit` y `abort` desde un hilo terminan el proceso

**Estado:** hecha. Ficha de [T80](../T80-proc-macros.md).

## Reproducción

Un `abort()` o `exit` en el hilo del compilador de rustc sólo terminaba ese hilo (`SYS_EXIT` es la salida de hilo). Si el hilo moría con el candado del backtrace cogido, el hilo principal se quedaba esperándolo para siempre (`guest-boot-cargo-19.txt`: todos los hilos de rustc en `park` / `lock_contended`); también dejaba hilos zombis tras `main`.

## Qué se hizo

`SYS_EXIT_GROUP` (95, nuevo; no sube `ABI_VERSION`): `task::exit_group` mata a los demás hilos del espacio de direcciones y sale con el código. `soso_rt::exit_group`/`abort`, `process::exit` (`sys/exit.rs`) y el fin de `main` de la PAL lo usan. `thread_start` sigue con `SYS_EXIT`.

## Evidencia

`guest-cargo-build-20.txt`: el fallo de rustc ya llega a cargo como error (`memory allocation of 448 bytes failed`) en vez de colgarlo.

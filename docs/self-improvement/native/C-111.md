# C-111 — Entorno de los hijos y de `std::env`

**Estado:** hecha.

## Reproducción

Un `build.rs` no veía `OUT_DIR` ni los `CARGO_*`: `spawn_soso` pasaba
`envp_ptr: 0`, y además `std::env::vars()` salía siempre vacío porque la ruta de
arranque real (`soso_entry_from_kernel`) no recibe `envp`.

## Qué se hizo

- `spawn_soso` pasa el entorno completo (el actual más los cambios de
  `Command::env`) cuando hay cambios; si no, se hereda (`apply-patches.sh`).
- `SYS_GETENV` con clave vacía devuelve el bloque entero del proceso;
  `sys/env/soso.rs` lo usa al arrancar (`cargar_del_kernel`).
- El kernel admite hasta 1024 variables y 64 KiB (antes 256 y 4 KiB).

## Evidencia

`guest-cargo-build-48.txt` (`/tmp/e` imprime `FOO=bar`, `HOME=/`, `PATH=/bin:/sbin`)
y `guest-cargo-build-61.txt` (`build.rs` con `rustc-env`).

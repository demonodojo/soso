# C-138 — Leer un fichero abierto para escribir; `O_TRUNC` sobre uno existente

**Estado:** hecha (2026-10-04). Ficha de [T42](../T42-c-link-imagen.md).

## Reproducción

`imagen` (`bootloader::DiskImageBuilder`) fallaba en el guest con «Failed to open FAT file system … bad file descriptor (os error 9)»: `fatfs` abre su imagen con `read(true).write(true).truncate(true)`, la formatea y la relee. El PAL abre eso como `O_WRONLY`; el kernel devolvía EBADF al leer un `WriteBuf`, y además un fichero que ya existía abierto con `O_TRUNC` caía en `StreamWrite` (sólo añade, no se lee).

## Qué se hizo

`kernel/src/task/syscall.rs`: `sys_read` lee un `Fd::WriteBuf` de la caché por inodo; `sys_open` manda a `WriteBuf` (vaciándolo) también los ficheros existentes abiertos con `O_TRUNC` sin `O_APPEND` (salvo `/var/models`).

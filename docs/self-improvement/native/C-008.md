# C-008 — `rustc_codegen_llvm` no compila en soso

**Estado:** hecha.

## Reproducción

Tras C-007, `./x.py check compiler/rustc --host x86_64-unknown-soso`
(`target/self-improvement/tasks/T40/check-host-11.txt`, exit 1, 36 errores
en `rustc_codegen_llvm`). El primero:

```
error[E0432]: unresolved import `libc::c_uint`
 --> compiler/rustc_codegen_llvm/src/abi.rs:3:5
  |
3 | use libc::c_uint;
  |           no `c_uint` in the root
```

El mismo crate tampoco encontraba `c_char`, `c_int`, `c_longlong`, `c_uchar`,
`c_ulonglong`, `size_t` ni `libc::free`. `libloading::Library` sólo existe
en unix y Windows (`offload_ffi.rs`, `enzyme_ffi.rs`).

`libc` para un target no soportado deja el módulo vacío. soso caía ahí.

## Qué se hizo

`apply-patches.sh` copia `libc` 0.2.189 a `src/soso-libc` y lo engancha con
`[patch.crates-io]`. La rama de soso publica los primitivos C (`primitives`)
más `size_t` (`usize`) y `free`. `free` no libera: no hay libc de C.

Offload y Enzyme, en soso, devuelven error de carga en vez de
`libloading::Library`. El resto de targets sigue cargando la biblioteca.

`check-host-12.txt` negó `unreachable_pub` en `pub use new::*`.
`check-host-13.txt` negó dos macros de Enzyme sin uso. `check-host-14.txt`:
exit 1, 64 s. Esos símbolos ya no fallan. El check se para en
`path_to_c_string`, que C-003 dejó fuera de soso. Eso es C-009, sin
implementar.

**Límite.** `free` no devuelve la memoria. Offload y Enzyme no cargan.

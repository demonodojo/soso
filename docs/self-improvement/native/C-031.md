# C-031 — `rustc` no encuentra el sysroot

**Estado:** hecha.

## Reproducción

Tras C-030, en el guest (`guest-rustc-emit-22.txt`):

```
$ rustc --emit=obj -o /tmp/t.o /tmp/t.rs
thread 'main' (1) panicked at compiler/rustc_session/src/filesearch.rs:375:60:
Failed finding sysroot: "dll_path is not supported on soso"
sosh: [rustc salió con código 134]
```

`default_from_rustc_driver_dll` usa `dll_path`. En soso esa función devuelve
error (C-004). `rustc --version` sí imprime `rustc 1.100.0-nightly`.

## Qué se hizo

En soso, `default_sysroot` no llama a `dll_path`. El ejecutable sale de
`argv[0]`: si no es absoluto, del primer directorio de `PATH`, y si no hay
`PATH`, de `/bin`. El sysroot es el padre de `bin/`. `std` de soso no
implementa `stat`, así que no se usa `is_file` ni `exists`.

`build-host-24.txt`: exit 0, 1 min 38 s. `guest-rustc-emit-24.txt`: el
pánico de `dll_path` ya no sale. `rustc --emit=obj` aborta con código 134
porque `std::env::current_dir` devuelve
`operation not supported on this platform`
(`config.rs`, `Current directory is invalid`). Eso es C-032, sin implementar.

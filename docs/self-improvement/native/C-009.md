# C-009 — `path_to_c_string` no existe en soso

**Estado:** hecha.

## Reproducción

Tras C-008, `./x.py check compiler/rustc --host x86_64-unknown-soso`
(`target/self-improvement/tasks/T40/check-host-14.txt`, exit 1):

```
error[E0432]: unresolved import `rustc_fs_util::path_to_c_string`
   --> compiler/rustc_codegen_llvm/src/back/write.rs:21:35
    |
 21 | use rustc_fs_util::{link_or_copy, path_to_c_string};
    |                                   no `path_to_c_string` in the root
```

El mismo import faltaba en `compiler/rustc_codegen_llvm/src/llvm_util.rs:14`.

C-003 dejó `path_to_c_string` en unix, WASI p1 y Windows. `rustc_codegen_llvm`
sí lo llama.

## Qué se hizo

En soso la función convierte el camino con `std::os::soso::ffi::OsStrExt`,
igual que unix con sus bytes. Unix, WASI y Windows no cambian.

`check-host-15.txt` aún veía `NotFound` de offload sin construir (el stub de
C-008). `check-host-16.txt`: exit 1, 77 s. `Checking rustc_codegen_llvm`
pasa. El check se para en el crate `ctrlc`. Eso es C-010, sin implementar.

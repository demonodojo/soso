# C-005 — `libloading` no exporta `Library` en soso

**Estado:** hecha (no se cargan bibliotecas dinámicas).

## Reproducción

Tras C-004, `./x.py check compiler/rustc --host x86_64-unknown-soso`
(`target/self-improvement/tasks/T40/check-host-6.txt`, exit 1):

```
error[E0425]: cannot find type `Library` in crate `libloading`
  --> compiler/rustc_metadata/src/host_dylib.rs:16:58
note: found an item that was configured out
  --> libloading-0.9.0/src/lib.rs:65:22
   |
64 | #[cfg(any(unix, windows, libloading_docs))]
```

## Arreglo

`config/rust-soso/compiler/rustc_metadata/src/host_dylib.rs` deja la carga
con `libloading` en unix y Windows. En soso `load_symbol_from_dylib`
devuelve `DlOpen`: no hay bibliotecas dinámicas. `lib.rs` no pide
`error_iter` fuera de esas plataformas y, en soso, nombra `libloading`
para que la dependencia no quede muerta. `apply-patches.sh` copia los dos
ficheros.

## Comprobación

`check-host-8.txt` (exit 1, 53 s): `Checking rustc_metadata` pasa. El
siguiente error es C-006.

## Límite

Las proc macros no se pueden cargar en soso. El compilador que llegue a
pedir una fallará en ejecución con ese `DlOpen`.

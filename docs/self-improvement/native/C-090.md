# C-090 — enlace del bin `cargo` sin `-lstdc++` (`-lz`/`-lc`/…)

**Estado:** hecha.

## Reproducción

Tras C-089, `build-cargo-54.txt` / `55.txt`: lib y bin `cargo` compilan;
falla el enlace con `wild-soso`:

```
wild: error: Couldn't find library 'z' on library search path
```

rustc pasa `-Bdynamic -lz -lc -lm -lrt -lpthread` sin `-L` del host cuando
no hay `-lstdc++` (enlace distinto al de `rustc` con C++).

## Qué se hizo

En `tools/wild-soso`:

- `with_lib_dir_before` / `with_host_lib_search_dirs`: `-L` de
  `cc -print-file-name=…` delante de cada `-l*` ya presente.
- `with_static_host_libs`: `-Bstatic` también delante de `-lz`/`-lc` tras
  `-Bdynamic` (guest sin cargador Linux).
- `needs_gcc_crt`: activa `crtbegin`/`crtend` en esos enlaces (no sólo con
  `-lstdc++`).
- `with_crtbegin`: inserta `crtbegin.o` **después** de `-flavor gnu`, no al
  inicio (log 58: `wild: unrecognized option(s): -flavor`).
- `with_host_libgcc_eh`: si `needs_gcc_crt` y no hay `-lstdc++`, añade
  `libgcc_eh.a` tras `-lpthread` (`__register_frame`, log 59).
- `without_bdynamic` + `--static` (wild) para ejecutables guest sin `NEEDED`
  (`build-cargo-62.txt`; relink tras borrar `release/cargo` y deps).

## Evidencia

- `build-cargo-60.txt`: `./x.py build cargo --host x86_64-unknown-soso`, exit 0.
- `build-cargo-62.txt`: cargo estático (~37 MiB), `readelf -d` sin `NEEDED`.
- Guest: `rustc --version` OK; `cargo -V` page fault en arranque
  (`guest-boot-cargo-4.txt`) — runtime, no enlace.

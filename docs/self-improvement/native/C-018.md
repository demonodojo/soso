# C-018 — `wild` no acepta `-Wl,-z,origin` ni `-Wl,-rpath`

**Estado:** hecha.

## Reproducción

Tras C-017, `./x.py build compiler/rustc --host x86_64-unknown-soso -j 8`
(`target/self-improvement/tasks/T40/build-host-8.txt`, exit 1, 0 s):

```
error: linking with `.../target/release/wild-soso` failed: exit status: 255
  = note: wild: error: unrecognized option(s): -Wl,-z,origin, -Wl,-rpath,$ORIGIN/../lib
```

Esas dos opciones salen de los `-Clink-args` del bootstrap
(`-Wl,-z,origin` y `-Wl,-rpath,$ORIGIN/../lib`). `wild-soso` las pasaba a
`wild`, y `wild` no las reconoce. El prefijo `-Wl,` es de gcc: el
enlazador recibe los trozos separados por coma.

## Qué se hizo

`tools/wild-soso` parte cada argumento `-Wl,…` en las opciones que gcc le
pasaría al enlazador. `-Wl,-z,origin` queda `-z` `origin`;
`-Wl,-rpath,$ORIGIN/../lib` queda `-rpath` `$ORIGIN/../lib`.

`build-host-9.txt`: exit 1, 0 s. Esas dos opciones ya no salen en el error
de `wild`. El enlace pide `-lstdc++` y `wild` no encuentra la biblioteca.
Eso es C-019, sin implementar.

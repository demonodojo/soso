# C-082 — Reconstruir `libstd` cruzada para soso con stage0

**Estado:** en curso.

## Reproducción

Tras C-081, `./x.py build cargo --host x86_64-unknown-soso --keep-stage-std 1`
con `--build-dir …/T40/build` falla antes de validar crates de Cargo:

```
error[E0460]: found possibly newer version of crate `alloc` which `std` depends on
  crate `std`: .../ci-rustc-sysroot/.../libstd-4c67af3cfb8049d2.rmeta
```

El `.libstd-stamp` apuntaba a hashes `c0d12…` sin artefactos; mezclar `libstd`
y `alloc` de sesiones distintas deja el sysroot incoherente para el rustc de
CI (stage1 tools).

Reconstruir con `./x.py build library --stage 1` sin parche usaba el rustc de
CI para `std` (`E0725`, features no permitidas) o stage0 con
`const_eval_long_running` / errores masivos en `core`/`std`.

## Qué se hizo

- `apply-patches.sh`: en `Std::run`, target `soso` + `download-rustc` compila
  la librería con **stage0** (bootstrap), no stage1 CI.
- Mismo script: `-Along_running_const_eval` en builds `Mode::Std` para soso
  (stdarch AVX512 bajo `build.warnings = deny`; el beta CI no reconoce el lint
  antiguo `const_eval_long_running`).

## Evidencia

- `build-std-soso-1.txt`: arranca `Building stage0 library artifacts … -> stage0:x86_64-unknown-soso`; sigue fallando (`E0725` en `std`, luego `core`).
- `build-cargo-38.txt` / `39.txt`: bloqueo en sysroot (`E0460`), no llega a cerrar C-081 en log.

## Qué falta

Sysroot soso coherente (rebuild stage0 std completo o restaurar stamp +
artefactos de una sola sesión en `build-soso`), luego `./x.py build cargo
--host x86_64-unknown-soso --keep-stage-std 1` y evidencia de
`cargo-util-terminal` en verde.

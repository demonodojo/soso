# C-020 — `_start` duplicado entre `rustc-main` y `libstd`

**Estado:** hecha.

## Reproducción

Tras C-019, `./x.py build compiler/rustc --host x86_64-unknown-soso -j 8`
(`target/self-improvement/tasks/T40/build-host-10.txt`, exit 1, 0 s):

```
error: linking with `.../target/release/wild-soso` failed: exit status: 255
  = note: wild: error: Duplicate symbols detected: _start, defined in
          .../rustc_main-....rustc_main.e8f192fd38cca8ab-cgu.0.rcgu.o
          and .../ci-rustc-sysroot/lib/rustlib/x86_64-unknown-soso/lib/libstd-c0d12c2bb54f24f0.rlib
          @ std-c0d12c2bb54f24f0.std.a2b71c03263228f6-cgu.0.rcgu.o
```

El target pedía `entry-name: "_start"`, así que rustc emitía ese símbolo en
el binario. La PAL de soso ya define `_start` (entrada del kernel) y llama
a `main`.

## Qué se hizo

`targets/x86_64-unknown-soso.json` pasa `entry-name` a `main`, que es el
símbolo que llama la PAL. La copia que usa el build está en
`~/.cache/soso-rust-vendor/x86_64-unknown-soso.json`.

`build-host-11.txt`: exit 1, 1 s. `_start` ya no está duplicado. `wild`
deja `free` sin definir, referenciado por `SpeculativeExecution.cpp.o`
dentro de `rustc_llvm`. Eso es C-021, sin implementar.

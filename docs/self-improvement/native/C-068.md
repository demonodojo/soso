# C-068 — `getrandom` sin backend para soso en el workspace de Cargo

**Estado:** hecha.

## Reproducción

`./x.py build cargo --host x86_64-unknown-soso -j 1 --build-dir
target/self-improvement/tasks/T40/build` con la fuente de Cargo en
`3c0b534756e1` (submódulo `src/tools/cargo`, sin inicializar hasta
2026-09-29). `target/self-improvement/tasks/T41/build-cargo-1.txt`, exit 1,
50 s:

```
error: target is not supported, for more information see: https://docs.rs/getrandom/#unsupported-targets
  --> getrandom-0.2.17/src/lib.rs:351:9
error: could not compile `getrandom` (lib) due to 1 previous error
```

El parche de C-002 (`[patch.crates-io] getrandom = { path = "src/soso-getrandom" }`)
sólo cubre 0.3.3 y va en el `Cargo.toml` de la raíz de rust. El workspace de
Cargo tiene su propio `Cargo.lock` con tres versiones: 0.2.17, 0.3.4 y 0.4.3.

## Qué se hizo

Tres árboles en `config/rust-soso/vendor/getrandom-{0.2,0.3,0.4}` con backend
`soso` (`SYS_GETRANDOM`, 78). `apply-patches.sh` los copia a
`src/soso-getrandom-*`, parchea el lock del submódulo Cargo (referencia) y
ejecuta `patch-getrandom-registry.sh`, que sobrescribe las tres versiones en
`$CARGO_HOME/registry` (el bootstrap regenera el lock y no usa los path del
submódulo).

## Evidencia

Tras `patch-getrandom-registry.sh`, `./x.py build cargo --host
x86_64-unknown-soso` (`build-cargo-4.txt`, exit 1, ~1 s): `getrandom v0.2.17`
compila; el primer error pasa a `gix-config-value` (C-069).

## Qué falta

Automatizar el parche del registry dentro del bootstrap (hoy hace falta el
script tras el primer fetch). C-069.

# C-032 — `rustc` no obtiene el directorio de trabajo

**Estado:** hecha.

## Reproducción

Tras C-031, en el guest (`guest-rustc-emit-24.txt`):

```
$ rustc --emit=obj -o /tmp/t.o /tmp/t.rs
error: Current directory is invalid: operation not supported on this platform
sosh: [rustc salió con código 134]
```

`compiler/rustc_session/src/config.rs` llama a `std::env::current_dir`. En
soso el `fs` de `std` es el módulo `unsupported`, y `sys/paths/unsupported.rs`
hace lo mismo con `getcwd`.

## Qué se hizo

`library/std/src/sys/paths/soso.rs` implementa `getcwd` con `SYS_GETCWD`.
`sys/paths/mod.rs` lo usa en soso. `split_paths`, `current_exe` y `temp_dir`
siguen en `unsupported`.

`build-host-26.txt`: exit 0, 1 min 38 s. `guest-rustc-emit-26.txt`: el error
del directorio ya no sale. `rustc --emit=obj` entra en pánico en
`std::process::id` (`sys/process/unsupported.rs:335`, «no pids on this
platform»), al nombrar el fichero de un informe ICE
(`rustc_driver_impl` línea 1426). Eso es C-033, sin implementar.

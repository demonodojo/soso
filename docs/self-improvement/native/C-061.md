# C-061 — `perm` entra en pánico al enlazar

**Estado:** hecha.

## Reproducción

Tras el paso 4, en el guest (`guest-rustc-link-90.txt`) `rustc
/tmp/t.rs -o /tmp/t` con

```
fn main() { println!("hola-t40"); std::process::exit(7); }
```

entra en pánico en `library/std/src/sys/fs/soso.rs:70`:

```
permisos de fichero no disponibles en soso
```

rustc sale con 134 y el hilo que espera el resultado entra en
pánico (`el hilo de rustc no dejó resultado`). `ls /tmp` muestra
los objetos temporales y no muestra `/tmp/t`.

`FileAttr::perm` hace `panic!`. `FilePermissions` es un tipo
vacío (`!`), así que no hay un valor que devolver.

## Qué se hizo

`FilePermissions` guarda un `readonly`. `perm` devuelve un valor
escribible: soso no tiene bits de permiso. `set_perm` y
`set_perm_nofollow` devuelven `unsupported` en lugar de agotar el
tipo vacío. Hubo que recompilar rustc (`build-host-54.txt`).

`guest-rustc-link-91.txt`: el pánico de `perm` ya no aparece.
rustc sigue saliendo con 134, ahora en
`rustc_codegen_ssa/src/back/linker.rs:135` (`JoinPathsError`).
Eso es C-062, sin implementar. T40 no se cierra.

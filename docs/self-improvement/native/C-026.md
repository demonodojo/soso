# C-026 — el `rustc` enlazado depende de bibliotecas del host

**Estado:** hecha.

## Reproducción

Tras C-025, `./x.py build compiler/rustc --host x86_64-unknown-soso -j 8`
(`target/self-improvement/tasks/T40/build-host-16.txt`, exit 0, 0 s). El
binario era

`target/self-improvement/tasks/T40/build/x86_64-unknown-soso/stage2/bin/rustc`

(224202418 bytes, ELF dinámico). `readelf -d` (`rustc-soso-needed.txt`):

```
NEEDED  libstdc++.so.6
NEEDED  libm.so.6
NEEDED  libz.so.1
NEEDED  libc.so.6
NEEDED  ld-linux-x86-64.so.2
RUNPATH $ORIGIN/../lib
```

Esas bibliotecas son del host. El guest no tiene ese cargador. rustc ya
pasaba un `-Bstatic` para los rlib y luego `-Bdynamic` delante de
`-lstdc++`.

## Qué se hizo

Si el enlace pide `-lstdc++` y el argumento anterior no es `-Bstatic`,
`tools/wild-soso` inserta `-Bstatic` justo antes. Así `libstdc++`, `libm`,
`libz` y `libc` que siguen van estáticas.

`build-host-19.txt`: exit 1, 0 s. `wild` ya usa
`/usr/lib/gcc/x86_64-linux-gnu/13/libstdc++.a`. El enlace no deja el binario
en `stage2/bin/rustc`. El símbolo que falta es `_Unwind_Resume`,
referenciado por `sstream-inst.o` de esa `libstdc++.a`. Eso es C-027, sin
implementar.

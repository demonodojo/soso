# C-006 — `libc` no tiene `size_t` en soso

**Estado:** hecha.

## Reproducción

Tras C-005, `./x.py check compiler/rustc --host x86_64-unknown-soso`
(`target/self-improvement/tasks/T40/check-host-8.txt`, exit 1):

```
error[E0432]: unresolved import `libc::size_t`
 --> compiler/rustc_llvm/src/lib.rs:8:5
  |
8 | use libc::size_t;
  |           no `size_t` in the root
```

`rustc_llvm` importa `size_t` de `libc`. El crate `libc` no lo publica para
`target_os = "soso"`. En x86_64 ese tipo es `usize`. El único uso en el crate
es el argumento de `LLVMRustStringWriteImpl`, que `slice::from_raw_parts`
recibe como `usize`.

## Qué se hizo

`apply-patches.sh` deja el import de `libc::size_t` en el resto de targets.
En soso define `pub type size_t = usize` y nombra `libc` para que el check no
niegue el aviso de dependencia sin uso. El nombre conserva `size_t` con
`allow(non_camel_case_types)`.

`check-host-9.txt` aún veía esos dos avisos. `check-host-10.txt`:
`Checking rustc_llvm` pasa. El check sigue en exit 1 por `rustc_sanitizers`.
Eso es C-007, sin implementar.

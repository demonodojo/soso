# C-011 — `rustc_driver` es sólo `dylib`

**Estado:** hecha.

## Reproducción

Tras C-010, `./x.py check compiler/rustc --host x86_64-unknown-soso`
(`target/self-improvement/tasks/T40/check-host-18.txt`, exit 1):

```
warning: dropping unsupported crate type `dylib` for target `x86_64-unknown-soso`

error[E0463]: can't find crate for `rustc_driver`
  --> compiler/rustc/src/main.rs:36:1
   |
36 | rustc_driver::override_c_allocator_in_binary!();
   | can't find crate
```

`compiler/rustc_driver/Cargo.toml` declaraba `crate-type = ["dylib"]`. El
target soso no admite dylib, así que no quedaba artefacto.

## Qué se hizo

`apply-patches.sh` deja el `dylib` y añade `rlib`. En soso el dylib se
descarta y `rustc-main` enlaza el `rlib`. En un host que sí admite dylib
siguen produciéndose los dos.

`check-host-19.txt`: exit 0, 78 s. `Checking rustc-main` termina.
`Finished`. El aviso de descartar el dylib sigue; no para el check.

**Límite.** El check de host soso ya sale 0. rustc no arranca en el guest.
T40 no se cierra.

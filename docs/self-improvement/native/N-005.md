# N-005 — Carga de código ajeno: el experimento

**Backlog:** [backlog.json](backlog.json) · **Prioridad:** 5 · **Depende de:** nada.
**Aplica en:** soso · **Origen:** [T32](../T32-opencode-inventario.md).
**Tipo:** experimento con **resultado binario**. Condiciona N-006 y N-007.

La pregunta: *¿se puede enlazar estáticamente todo lo nativo que un runtime
necesita, o hace falta carga dinámica?*

## Resultado: **enlazado estático**. `dlopen` no existe y nada obliga a tenerlo

Las dos mitades se miden por separado porque fallan por separado, y cada una
lleva su control.

### Lo que sí: C ajeno compilado y enlazado corre

`soso-agent-probe carga`, con un fichero C escrito para la ocasión
(`user/soso-agent-probe/c/ajeno.c`) compilado hacia `x86_64-soso-user` y
enlazado en la sonda:

    carga/c-ajeno-compilado-y-enlazado            ok  286d4b6114e61fc3
    carga/c-ajeno-escribe-en-memoria-del-llamante ok  [26, 1, dc, b7, …]

El C no devuelve una constante: es un FNV-1a sobre 64 bytes que dependen de la
entrada, comparado contra el mismo cálculo hecho en Rust — **no** contra un
número copiado de la primera ejecución, que habría hecho pasar el caso para
siempre. El segundo caso escribe en memoria del llamante pasando por `memcpy`,
para que el enlace no sea sólo de lectura.

Se compila un fichero **nuevo** a propósito. `soso-http` ya enlaza el C de
`ring` desde hace tiempo, pero eso llegó dentro de una dependencia: mediría la
herencia, no la capacidad.

### Lo que no: un ELF que no sea `ET_EXEC` no arranca

    carga/copia-intacta-arranca  ok  arrancó y salió con 7
    carga/un-et-dyn-no-arranca   ok  no arrancó: argumento inválido (-22)

El experimento es de **un byte**: se copia el propio binario de la sonda, se
arranca (control), y después se cambia `e_type` de 2 (`ET_EXEC`) a 3
(`ET_DYN`) —byte 16— y se vuelve a intentar. Todo lo demás es idéntico: la
ruta, el tamaño, los permisos, el contenido.

Sin el control, «el ET_DYN no arrancó» sería compatible con «nada de /tmp
arranca», que es una conclusión distinta. Con él, la única diferencia entre lo
que corre y lo que no es ese byte.

## Cuánta libc pide el C que ya está dentro

`nm -u` sobre los **31 objetos** de C de `ring` compilados para el target de
soso, quitando sus propios símbolos
(`target/self-improvement/tasks/N-005/libc-superficie.txt`):

    memcpy
    memset
    __stack_chk_fail

Tres. `memcpy` y `memset` los pone `compiler-builtins-mem` (activado en
`user/.cargo/config.toml`); `__stack_chk_fail` está escrito a mano en
`user/libsoso/src/lib.rs`, con el comentario que ya guarda la lección del
`%fs:0x28`.

Y el binario que sale es `ET_EXEC`, tres `PT_LOAD`, **sin `PT_INTERP` y sin
sección dinámica**. No hay enlazador dinámico al que llamar porque no hay nada
que enlazar en ejecución.

**Cuidado con generalizar este tres.** `ring` está escrito para ser
*freestanding*: no llama a `malloc`, no usa `stdio`, no toca `errno`. Una
biblioteca C cualquiera pide mucho más. Lo que el número acota es el **suelo**,
no el techo: es lo que cuesta el C que ya está dentro, y por tanto la prueba de
que el camino existe — no una estimación de N-006.

## Lo que esto decide, y lo que no

**Decide** que N-006 y N-007 se construyen sobre enlazado estático: una capa
libc para código C que se compila *con* el programa, no un cargador. Añadir
`dlopen` costaría parsear `PT_DYNAMIC`, procesar reubicaciones, resolver
símbolos y generar código PIC —el target de soso tiene
`position-independent-executables: false` y `relocation-model: static`, así que
tampoco es un interruptor—, y **nada del inventario lo pide**: los `.node` de
OpenCode no son «código nativo que hay que cargar», son binarios compilados
para otro sistema operativo. Recompilarlos es un problema de libc, no de carga.

**No decide** que cualquier biblioteca C valga. Eso lo mide N-006 pasando las
siete sondas de T33 desde C, y ahí es donde aparecerá lo que falte.

**Tampoco dice que `dlopen` sea imposible**, sino que no está y que ninguna de
las fichas del backlog lo necesita para avanzar. Si algún día llega un
consumidor que sí —un sistema de plugins cargados en caliente—, esta ficha deja
medido lo que costaría: todo, porque hoy no hay ni una pieza.

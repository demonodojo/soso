# C-004 — `dll_path` no existe en soso

**Estado:** hecha (stub; no hay `dladdr`).

## Reproducción

Tras C-003, `./x.py check compiler/rustc --host x86_64-unknown-soso`
(`target/self-improvement/tasks/T40/check-host-5.txt`, exit 1):

```
warning: unused import: `rustc_fs_util::try_canonicalize`
 --> compiler/rustc_session/src/filesearch.rs:7:5

error[E0425]: cannot find function `dll_path` in this scope
   --> compiler/rustc_session/src/filesearch.rs:273:34
```

`dll_path` está bajo `cfg(unix)`, Windows o WASI. `current_dll_path` la
llama igual. `try_canonicalize` sólo se usa dentro de las ramas unix y
Windows, así que en soso el import queda muerto y el check niega avisos.

## Arreglo

`apply-patches.sh` añade `dll_path` para `target_os = "soso"`, que devuelve
error igual que WASI: soso no tiene `dladdr`. El import de
`try_canonicalize` queda en `cfg(any(unix, windows))`, que es donde se usa.

## Comprobación

`check-host-6.txt` (exit 1, 43 s): `rustc_session` ya no aparece en el
fallo. El siguiente error es C-005.

## Límite

El sysroot no se puede deducir de la biblioteca del driver. Sigue el camino
de `argv`. No hay `dladdr` que implementar aquí.

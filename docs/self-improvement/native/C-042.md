# C-042 — pthread_once usa el futex de Linux

**Estado:** hecha.

## Reproducción

Tras C-041, en el guest (`guest-boot-44.txt`) el hilo principal muere en
`abort`. `__pthread_once_slow` espera con la syscall 202 de Linux
(`FUTEX_WAIT` privada) y el código que vuelve no es éxito, `EAGAIN` ni
`EINTR`. glibc llama a `__libc_fatal` con «The futex facility returned
an unexpected error code.» `rustc` sale con código 255
(`guest-rustc-emit-44.txt`).

## Qué se hizo

La syscall 202 se traduce al futex de soso. `FUTEX_WAIT` (0) y
`FUTEX_WAKE` (1) pasan, con o sin el bit privado. Linux pone la
dirección en el primer argumento y la operación en el segundo; soso al
revés. El plazo nulo sigue siendo espera infinita.

`guest-boot-45.txt`: ese `abort` ya no sale. El hilo principal muere
con page fault en `memset` (`rep stos`), `va=0x100011d000`, dirección
sin región mmap. `guest-rustc-emit-45.txt`: código 255. Eso es C-043,
sin implementar.

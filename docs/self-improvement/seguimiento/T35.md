Además el `Procesos` del host ahora **aplica `timeout_s`** (mata al hijo y devuelve lo que llevaba, con `motivo`).

**Pruebas.** `cargo test -p soso-improve-core --test agente`: 9/9 (entorno en memoria + modelo guionizado). `cargo test -p soso-improve-core -p soso-improve --no-fail-fast`: todo verde salvo `receta` (2 tests, preexistentes, ficha propia).

**Modelo real.** `tests/self-improvement/opencode/t35-agente-3/` (`host-agente.sh`, `sesion.json`, `parche.diff`): 14B en el host (HILOS=4), temperatura 0, R03: `read TASK.md → grep → read tramo → reemplazar_texto → cargo test` y respuesta final; **verificador R03 exit 0**, 6 turnos, 5 llamadas, 2749 s (casi todo prefill en frío). ## 2026-10-11 · cierre: el agente ELF dentro del guest con el modelo del guest

`cargo xtask test-agent-native` (= `test-llm-api --agente-nativo`, 14B, QEMU 14G/4 núcleos): siembra `/tmp/g` desde una sesión, **ejecuta `soso-improve agente` en el guest** contra el `soso-llm serve` del mismo guest (`read` → `reemplazar_texto` → informe, 3 turnos), y **otra sesión SSH** lee `src/lib.rs` y ve `eq_ignore_ascii_case`; `/tmp/g/.sesion` tiene tres generaciones `sesion.json.*`. 898 s. Evidencia: `tests/self-improvement/opencode/t35-agente-en-guest/`. Primeros intentos: `--orden` con `ssh <comando>` falló porque el SSH de soso no tiene `exec` (sólo shell interactiva): se pasó al arnés Rust con `ssh_guion`; el primer lanzamiento murió con la sesión y se repitió. Ficha **hecha**, `native_validation: partial` (límites en `resultado.md`). Siguiente: T25 (sobre el agente nativo) y T43.

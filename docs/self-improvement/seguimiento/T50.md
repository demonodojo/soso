## 2026-09-24 · intento 1

**Base:** commit `95de3c162` + diff sucio. **Por qué ésta:** de las habilitadas,
es la que más desbloquea (T24, T39, T51).

### Lo entregado

`crates/soso-improve-core/src/delta.rs`: `Operacion` (alta, modificación,
borrado, cada una con sus hashes), `Paquete` (base, destino, operaciones), y
`validar` / `aplicar` / `exportar` / `inventario_resultante`.

El orden importa y es el argumento central de la ficha: **validar entero antes
de escribir nada**. Base equivocada, objeto ausente, ruta duplicada, traversal
o ruta absoluta se rechazan en la validación, con el árbol original sin tocar.
Cada uno tiene su prueba, y cada prueba comprueba **que el árbol no cambió**,
no sólo que hubo error.

El metadato de Git puede viajar en el paquete para que un humano se sitúe;
`aplicar` no lo mira. Es lo que pide el paso 3: metadato, nunca requisito.

### Comparar hashes entre host y guest

El fixture vive en el crate **portable**, no duplicado en cada lado: si el host
y el guest usaran datos distintos, comparar sus huellas no diría nada. Su
huella está fijada como constante (`HUELLA_FIXTURE`) y la comprueban los dos.

Dentro de soso, sin Git instalado:

```
$ soso-improve delta
delta: huella f07a24b7…3abccd igual que en el host: ok
delta: contenido modificado: ok
delta: alta y borrado aplicados: ok
delta: base incorrecta rechazada: ok
delta: 0 caso(s) mal
```

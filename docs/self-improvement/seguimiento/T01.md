### Incidente (corregido)

Una versión intermedia de `reconstruct` pasaba rutas relativas a `git clone`
con otro cwd; el clone cayó en una ruta anidada y el `git checkout --detach`
siguiente se ejecutó en un directorio vacío sin repositorio, de modo que git
subió al checkout real y **desacopló su HEAD** (reflog 2026-09-15 23:01:20).
Corregido con rutas absolutas, comprobación de que el clone dejó repositorio,
`--git-dir/--work-tree` explícitos y `GIT_CEILING_DIRECTORIES` en todos los
comandos; con prueba de regresión y verificación de que la prueba tiene dientes.

## 2026-09-15 · las suites entran en `cargo xtask check`

Cambio pedido tras entregar T02, **fuera del alcance de T01 y T02**: las dos
fichas listan solo sus archivos bajo `scripts/` y `tests/`, y esto toca
`xtask/src/check.rs`. Queda escrito aquí en vez de ampliarlas en silencio.

**Por qué.** `cargo xtask check` es el único punto de entrada de verificación
del proyecto y no ejecutaba ninguna de las dos suites: podían pudrirse sin que
nadie se enterara. El contrato (C6) exige `cargo xtask check` antes de promover
una base, así que lo que no esté ahí dentro, de hecho no se comprueba.

**Qué se añadió.** `run_self_improvement` en `xtask/src/check.rs`, que ejecuta
`test_baseline.py` y `test_cases.py` con `PYTHONDONTWRITEBYTECODE=1` —para que
la propia comprobación no ensucie el checkout con `__pycache__`, que es justo
lo que T01 promete no hacer— y deja su log en `target/check-artefactos/`. Si
una suite no está en el árbol, se omite con aviso; si está y falla, `check`
falla.

**Por qué siguen en Python.** Las fichas lo fijan (T01: «Implementar con Python
estándar»), y hay una razón que se sostiene: la captura de base tiene que
funcionar cuando el build de Rust está roto, que es uno de los estados que
interesa fotografiar. Los datos del banco son JSON neutro, así que un port de
los verificadores a Rust —el sitio natural es `tools/soso-improve`, que C5 ya
planifica— no tocaría los 25 casos. Quedan cuatro fichas más que especifican
Python (T14, T21, T30, T39): si se decide unificar la pila, cuanto antes mejor.

**Evidencia:** `target/self-improvement/tasks/T02/xtask-check.log`.

## 2026-09-16 · port a Rust: la base también corre dentro de soso

**Por qué.** El objetivo del plan es que **todo** pueda ejecutarse dentro de
soso. Python no llega ahí: soso no tiene intérprete y portarlo no tiene sentido
frente a escribirlo en Rust. La implementación de T01 y T02 se reescribe, y las
fichas que aún pedían Python (T14, T21, T30, T39) se corrigen.

**Qué hay ahora.**

| Pieza | Qué es |
|---|---|
| `crates/soso-improve-core` | toda la lógica, `no_std + alloc`; habla con el sistema solo por los traits `Archivos` y `Procesos` |
| `tools/soso-improve` | binario host: `std::fs`, `std::process` y git |
| `user/soso-improve` | binario guest: `open`/`read`/`getdents`/`stat` y `spawn_io`+`wait` |

Es el patrón que ya usa `soso-http` con `TcpTransport`: la política en el crate
portable, el mecanismo en quien lo hospeda.

**Cambio de formato de la captura.** La versión Python describía la base como
`HEAD` + parches binarios y reconstruía con `git clone` + `git apply`. Eso no
puede funcionar en soso, donde `soso-git` solo sabe `status|log|diff|commit`.
Ahora la base se describe por lo que es —sus archivos y su contenido— en un
almacén direccionado por hash:

```
baseline.json          inventario, entorno, herramientas, huella
objetos/<aa>/<hash>    contenido, deduplicado entre capturas
```

Reconstruir es copiar objetos a sus rutas: sin git de por medio. Git se sigue
usando **cuando está**, solo para etiquetar la base (commit, rama, estado).

**Qué no es fuente.** Al no preguntarle a git, hay que saber qué tirar: se lee
el `.gitignore` del árbol (`crates/soso-improve-core/src/ignorar.rs`, un
subconjunto documentado que rechaza lo que no soporta en vez de leerlo mal).
Sin eso, la captura se tragaba `rootfs/var/` (137 MB de artefactos) y
`lxdde/reference/` (6600 archivos de fuentes ajenas).

**Medidas sobre este repositorio:** 1041 archivos, 10,7 MB, **1,2 s** para
capturar y **0,3 s** para reconstruir; comparación independiente archivo a
archivo: idénticos. La versión Python ocupaba menos (1,9 MB) pero necesitaba
clonar 316 MB de `.git` para reconstruir.

**Pruebas:** 34 en Rust (11 en el core, 8 de base, 15 de banco), ejecutadas por
`cargo xtask check` con el resto de tests host. El Python queda borrado.
